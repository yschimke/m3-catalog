# Cutover

**Done for the 50 ready stickers** (`cutover.py`, applied in this branch): each one's body in
`catalog/.../sections/<File>.kt` is now its generated sticker, with the same file, function name,
parameters and annotations. Verified after the cutover:

- every one of `:catalog`'s 4,139 preview ids is unchanged;
- all 4,170 of `:catalog`'s image captures, migrated or not, are pixel- and frame-identical to the
  renders before it;
- the discovered component record changes only in reverse links (`componentIds`) for calls that
  now happen inside generated components, and drops the derived `m3/current-scheme`, whose only
  call site was the colour grid.

`:catalog` builds from the checked-in generated source (`catalog/src/uid/kotlin`) with no exporter,
so nothing here waits on an upstream release. Regenerating after a document edit does:
`-PuidStickers=true … :uid-stickers:generateUidStickers`, and `verifyUidStickers` (in `check`)
fails when the checked-in source is stale.

## What "ready" means

- The shell in `src/main/kotlin/ee/schimke/m3catalog/uid/` has the hand-written sticker's
  function name, parameters and annotations, verbatim, so it publishes the same preview ids.
- Its body is a generated component (`build/generated/uid/kotlin`), exported by the UI builder's
  own exporter from `stickers/<name>.uid` plus that document's cells. The generated code holds no
  catalog helper: copy is string resources, knobs and click counters come in as parameters.
- `compare-local.py` found every capture identical.

## Regenerating

1. When the upstream changes are released, point `uidExportVersion` / `screenModelVersion` at the
   releases (today: Maven-local snapshots of compose-ui-builder #732 and compose-ai-tools #5896).
2. Edit `uid-stickers/stickers/<name>.uid` or its cells, run `generateUidStickers`, and commit
   `catalog/src/uid/kotlin` with the document.
3. The blocked stickers stay hand-written until the exporter grows their vocabulary; migrate one
   with `MIGRATING.md`, then put its shell into its `sections/` file the way `cutover.py` did.
